# Spines in their covers' colours Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spines in the stacks look bound, in two colours picked from each cover, with the whole title fitted on the label.

**Architecture:**
- **Server:** Python works out a two-colour palette from Loft's stored 480px cover copy whenever a cover is stored. It saves it in `books.spine_colors` and fills it in for existing books in a background thread at start.
- **API:** `book_card` carries it as `spine`.
- **Browser:** a new pure module `spines.js` chooses the label, letter and trim colours and fits the title using a measurer it is given. `stacks.js` renders the new markup and measures with one canvas.

**Tech Stack:** Python 3.14, Pillow, SQLite, FastAPI; vanilla JS ES modules; pytest; `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-23-spines-design.md`

## Global Constraints

- **Palette algorithm:**
  - Quantize a 72px-wide thumbnail to 8 colours (Pillow median cut).
  - `score = share × (0.6 + 2.2 × chroma)`, where `chroma = s × (1 − |2l − 1|)` (HLS).
  - base = the highest score.
  - accent = the highest score at RGB distance > 70 from base; otherwise base × 0.45.
  - No lightness cap.
- **Storage format:** `books.spine_colors TEXT`, `"#rrggbb #rrggbb"` (base then accent), NULL when there is no cover.
- **API:** `book_card` adds `"spine": ["#base", "#accent"]` or `None`.
- **Unchanged:** `cover_color` and everything that uses it (backgrounds, covers view, home rows).
- **Letter colour:** the best WCAG contrast on the label among gilt `#e2c27a`, ink `#1d150e` and paper `#f4ede2`.
- **Trim:** gilt, or bronze `#4a3a22` when gilt's contrast on the base is < 3.
- **No-palette fallback:**
  - base = `cover_color`, else `hsl(<hash(title) % 360> 32% 32%)` (today's);
  - label = base × 0.45;
  - letter = gilt or ink by contrast.
- **Title fitting:**
  - uppercase Literata 600, letter-spacing .05em, line-height 1.12;
  - sizes 12 → 7 in 0.5 steps;
  - greedy wrap into lines no longer than (label length − 12);
  - at most 3 lines, accepted when `lines × size × 1.12 ≤ width − 5`;
  - otherwise 7px with an ellipsis.
- **Layout percentages:**
  - ribs at top 8% and bottom 11%;
  - ornament ✦ at top 7.5%;
  - label from top 15% to bottom 18%, inset 2px each side;
  - number at bottom 5%.
- **Reference:** the visual reference is `.superpowers/brainstorm/3625828-1795454603/content/spines-a-colours.html` (option 1 row).
- **Saturate filter:** remove `filter: saturate(1.45)`.
- **Service worker:** `sw.js` cache becomes `loft-shell-v10`, and `spines` joins the SHELL list.
- **Books:** never read or write the book files for this. Palettes come only from `cfg.cover_dir/<id>-480.jpg`.
- **Commits:** end every message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit locally only; never push without the user asking.
- **Restart:** after Python changes, run `systemctl --user restart loft-test` (the test server on port 4545).

## Review Focus

1. **Covers that aren't plain RGB photos**: greyscale, palette PNG with transparency, a 1×1 image. Each must give a valid two-colour palette without raising. *(Task 1 test)*
2. **A cover cleared or replaced while the fill-in thread is running.** The fill must not write a palette for a book that no longer has a cover. *(Task 3 test)*
3. **A single word longer than the label even at 7px** (e.g. a 40-letter word on a short spine). The fitting returns the 7px fallback with `fits: false` and doesn't loop. *(Task 4 test)*
4. **A book with no cover and no `cover_color`.** The spine still gets base, label, letter and trim, from the title hash. *(Task 4 test)*
5. **Autofill undo of a fetched cover.** It clears `spine_colors` along with `cover_color`, so the spine doesn't keep the removed cover's colours. *(Task 2 test)*

from loft.covers import spine_colours, spine_palette

def _hex(s): return tuple(int(s[i:i + 2], 16) for i in (1, 3, 5))
def _near(a, b, tol=30): return all(abs(x - y) <= tol for x, y in zip(_hex(a), b))

def test_spine_palette_takes_the_covers_two_colours():
    img = Image.new("RGB", (60, 90), (160, 20, 20))
    img.paste((230, 190, 60), (0, 60, 60, 90))           # a third of it gold
    base, accent = spine_palette(img).split()
    assert _near(base, (160, 20, 20)) and _near(accent, (230, 190, 60))

def test_one_colour_cover_gets_a_deep_shade_for_its_label():
    base, accent = spine_palette(Image.new("RGB", (60, 90), (40, 90, 160))).split()
    assert _near(base, (40, 90, 160))
    assert _near(accent, (18, 40, 72), tol=4)             # base × 0.45

def test_white_cover_gives_a_light_spine():
    base, _ = spine_palette(Image.new("RGB", (60, 90), (245, 240, 230))).split()
    assert min(_hex(base)) > 200                          # not capped dark like cover_color

@pytest.mark.parametrize("img", [
    Image.new("L", (60, 90), 128),
    Image.new("RGBA", (60, 90), (10, 200, 10, 0)).convert("P"),
    Image.new("RGB", (1, 1), (9, 9, 9)),
])
def test_odd_images_still_give_a_palette(img):
    assert re.fullmatch(r"#[0-9a-f]{6} #[0-9a-f]{6}", spine_palette(img))

def test_spine_colours_reads_the_stored_cover(cfg):
    assert spine_colours(cfg, 7) is None
    store_cover(cfg, 7, jpg((160, 20, 20), (600, 900)))
    assert _near(spine_colours(cfg, 7).split()[0], (160, 20, 20))
    (cfg.cover_dir / "7-480.jpg").write_bytes(b"junk")
    assert spine_colours(cfg, 7) is None

### Task 4: Spine colours and title fitting (pure JS)

**Files:**
- Create: `src/loft/web/js/spines.js`
- Test: `tests/js/spines.test.mjs` (picked up by `tests/test_js.py`)

**Interfaces:**
- Produces:
  - `export const GILT = "#e2c27a", INK = "#1d150e", PAPER = "#f4ede2", BRONZE = "#4a3a22";`
  - `export function contrast(a: string, b: string): number`: the WCAG ratio of two `#rrggbb` colours.
  - `export function spineColours(b): { c, label, letter, trim }`:
    - `b` has `spine`, `color` and `title`;
    - all four results are `#rrggbb`, except `c` and `label`, which may be the `hsl(...)` fallback.
  - `export function fitTitle(title: string, length: number, width: number, measure: (text, size) => number): { size, lines, fits }`:
    - `measure` returns the width of `text` in uppercase Literata 600 at `size`, without letter-spacing;
    - `fitTitle` adds `0.05 × size` per character itself, uppercases, and splits on whitespace.

- [ ] **Step 1: Write the failing tests**

```js
import { test } from "node:test";
import assert from "node:assert/strict";
import { BRONZE, GILT, INK, PAPER, contrast, fitTitle, spineColours } from "../../src/loft/web/js/spines.js";

const measure = (text, size) => text.length * size * 0.6;   // a stand-in for the canvas

test("a short title stays big on one line", () => {
  assert.deepEqual(fitTitle("Unity", 120, 30, measure), { size: 12, lines: 1, fits: true });
});

test("a long title shrinks or wraps, but never past three lines or the spine's width", () => {
  const r = fitTitle("The Secret Crusade: Assassin's Creed Book 3", 110, 40, measure);
  assert.ok(r.fits && r.lines <= 3 && r.size < 12);
  assert.ok(r.lines * r.size * 1.12 <= 40 - 5);
});

test("a word too long for the label even at 7px falls back to 7px, cut", () => {
  assert.deepEqual(fitTitle("A".repeat(40), 60, 20, measure), { size: 7, lines: 1, fits: false });
});

test("an empty title is fine", () => {
  assert.equal(fitTitle("", 100, 20, measure).fits, true);
});

test("contrast is WCAG's", () => {
  assert.equal(Math.round(contrast("#000000", "#ffffff")), 21);
});

test("letters and trim stay readable on dark and light spines", () => {
  const dark = spineColours({ title: "x", spine: ["#5a1010", "#1a1a40"] });
  assert.equal(dark.c, "#5a1010"); assert.equal(dark.label, "#1a1a40");
  assert.equal(dark.letter, PAPER); assert.equal(dark.trim, GILT);   // paper beats gilt on a dark label, as in the mockup
  const cream = spineColours({ title: "x", spine: ["#efe6d2", "#f5f0e6"] });
  assert.equal(cream.letter, INK); assert.equal(cream.trim, BRONZE);
});

test("a book with no palette still gets a whole spine", () => {
  const old = spineColours({ title: "x", spine: null, color: "#402020" });
  assert.equal(old.c, "#402020"); assert.equal(old.label, "#1d0e0e");   // × 0.45
  const bare = spineColours({ title: "Untitled", spine: null, color: null });
  assert.match(bare.c, /^hsl\(\d+ 32% 32%\)$/);
  assert.ok(bare.label && bare.letter && bare.trim);
});
```

- [ ] **Step 3: Implement `spines.js`**

**Title-hash fallback:** the same FNV hash as `stacks.js`. Move `hash` here and export it; `stacks.js` imports it in Task 5.

**hsl fallback:** for an `hsl(h 32% 32%)` base, the label's × 0.45 and contrast work on its RGB. Convert with the standard HSL→RGB formula, and give `label` as `#rrggbb`.

**Fitting algorithm:**
1. For each size from 12 down to 7 in 0.5 steps, greedy-wrap the words:
   - a word wider than `length − 12` fails that size;
   - a new line starts when `run + space + word > length − 12`.
2. Accept the first size with `lines ≤ 3` and `lines × size × 1.12 ≤ width − 5`.
3. If no size fits, return `{ size: 7, lines: max(1, min(3, floor((width − 5) / (7 × 1.12)))), fits: false }`.

- [ ] **Step 3: Fitting after render**

Add `fitSpines(main)` in `stacks.js`, called after `main.innerHTML` is set (spines view only) and again on a `matchMedia("(max-width: 700px)")` change. Remove the listener on `hashchange`, like `onKey`.

It:
1. awaits `document.fonts.ready`;
2. reads one spine's `offsetHeight` and its `--tall` to get the row height `H` (the only layout read);
3. for each spine:
   - `length = H × tall/100 × (1 − .15 − .18) − 12`;
   - `width = --w`;
   - `measure` = one shared canvas with `ctx.font = \`600 ${size}px Literata\``;
4. writes `--fs`, `width = lines × size × 1.12` and `left = (width − block)/2`;
5. when `fits` is false, sets `white-space: nowrap` so the ellipsis shows.
